# Как написать плагин

Задача плана `4.0-I05`. Решение об API — [ADR 0010](../adr/0010-plugin-api.md).

Плагин — папка в `plugins/` с двумя файлами: `plugin.json` и `main.py`.

---

## Главное правило

**Плагин объявляет, а не делает.**

Он объявляет три вещи, и все три — данными:

- **инструменты** — что он умеет; уходят в реестр ядра и получают там
  разрешения, подтверждения и журнал наравне со встроенными;
- **страницу** — как он выглядит; описанием, без виджетов;
- **разрешения** — что ему нужно от машины; списком в манифесте, до
  первого запуска.

Почему так. Ядро спрашивает у человека согласие на «запуск программ» и
отказывает без него. Плагин, зовущий `subprocess` сам, обошёл бы это — и
тогда согласие человека было бы самообманом.

## Самый маленький плагин

`plugins/greeter/plugin.json`:

```json
{
  "id": "greeter",
  "name": "Приветствие",
  "version": "1.0.0",
  "api_version": 4,
  "description": "Отвечает на «привет»",
  "permissions": []
}
```

`plugins/greeter/main.py`:

```python
from plugins.api import Plugin


class GreeterPlugin(Plugin):
    def on_command(self, text):
        if "привет" in text.lower():
            self.ctx.respond("Привет! Чем помочь?")
            return True
        return False
```

`on_command` возвращает `True`, если фразу взял. Вернул `False` — фраза
идёт дальше по конвейеру.

Больше ничего не нужно: ни инструментов, ни страницы, ни разрешений.
Объявлять инструмент ради «привет» незачем, и API этого не требует.

## Инструмент

Инструмент — это то, что зовёт **ядро**, когда решит, что человек попросил
именно это. Плагин не решает, когда его инструменту работать.

```python
from core.tools import Param
from plugins.api import Plugin, PluginTool


class DicePlugin(Plugin):
    def tools(self):
        return [PluginTool(
            name="roll",
            description="Бросить кубик",
            params=(Param("faces", "integer", required=False, default=6),),
            returns="Выпавшее число",
            run=self._roll,
        )]

    def _roll(self, args):
        import random
        return random.randint(1, args["faces"])
```

Имя внутри плагина короткое: ядро само добавит префикс `plugin.dice.`,
чтобы два плагина с инструментом `roll` не спорили за одно имя.

Аргументы описываются теми же `Param`, что у встроенных инструментов, и
проверяются реестром — разбирать и доверять плагину не приходится.

## Разрешения

Каталог разрешений **один** — тот же, что у ядра (`core/permissions.py`).
Второй, «для плагинов», означал бы два языка об одном и том же.

Но доступно из него не всё. Никогда не выдаются:

- `system.power` — выключение и перезагрузка;
- `files.write` — запись файлов;
- `screen.read`, `input.synthesize` — зарезервированы под 5.0.

Инструмент, просящий недоступное, **не заводится вовсе**. Он всё равно
отказал бы, но уже после того, как человек его увидел и позвал.

Опасное разрешение обязано требовать подтверждения:

```python
PluginTool(name="clear", description="Стереть заметки",
           permissions=("plugin.state",), confirm_required=True,
           run=self._clear)
```

## Страница

Плагин описывает страницу списком элементов, а рисует их оболочка. Поэтому
плагин не импортирует ни Qt, ни WPF — и не пришлось переписывать ни одного
плагина, когда оболочка сменилась целиком.

```python
from plugins.page_spec import Card, Title, Note, Items, Button, Row


class NotesPlugin(Plugin):
    page_title = "Заметки"      # как назвать раздел в колонке

    def page(self):
        notes = self.ctx.get_setting("items", []) or []
        return [
            Card([
                Title("Мои заметки"),
                Note(f"Всего: {len(notes)}"),
                Items(notes) if notes else Note("Пока пусто"),
            ], title="Заметки"),
            Row([
                Button("Очистить", action="clear", variant="danger"),
                Button("Обновить", action="refresh"),
            ]),
        ]

    def on_action(self, action, value=None):
        if action == "clear":
            self.ctx.set_setting("items", [])
```

После действия страница пересобирается сама: плагин описывает своё текущее
состояние, а не следит за синхронизацией виджетов.

**Схема семантическая, а не визуальная.** Говорите «предупреждение», а не
«оранжевая рамка»; «карточка», а не «скруглить восемь пикселей». Полей о
внешности здесь нет и не будет: цвет, отступ и шрифт знает тот, кто рисует.

Все виды элементов — [PAGE-SCHEMA-v2](PAGE-SCHEMA-v2.md).

## Настройки плагина

Тоже описанием — панель строит оболочка:

```python
from plugins.settings_spec import Toggle, Text, Slider


def settings_schema(self):
    return [
        Text("prefix", "Приставка", default="•"),
        Toggle("timestamps", "Ставить время", default=True),
        Slider("limit", "Сколько хранить", min=10, max=500, default=100),
    ]
```

Значения хранит **ядро**, а не плагин: где они лежат — не его дело, и
заодно они переживают его собственное падение.

## Что доступно через `self.ctx`

| Метод | Что делает |
|---|---|
| `respond(text)` | Рина скажет и покажет текст |
| `log(message)` | строка в журнал плагина |
| `get_setting(key, default)` | своя настройка |
| `set_setting(key, value)` | записать свою настройку |
| `notify(title, message)` | уведомление |

Всё. Ни запуска программ, ни доступа к соседям, ни файловой системы: то,
что плагин умеет делать с миром, объявлено инструментами и проходит через
реестр.

## Жизненный цикл

```
    обнаружен  →  включён  →  работает  →  выключен
    (манифест     (процесс    (on_command,  (процесс
     прочитан,     поднят,     tools, page)  убит,
     код НЕ         on_enable)               инструменты
     запущен)                                сняты)
```

Код плагина запускается при **включении**, а не при обнаружении: иначе
сбойный плагин мешал бы уже старту Рины.

Хуки все необязательны: `on_enable`, `on_disable`, `on_command`,
`on_event`, `tools`, `page`, `on_action`, `settings_schema`.

## Плагин живёт в своём процессе

С `4.0-H07` каждый плагин — отдельный процесс. Ошибку можно поймать,
бесконечный цикл — нельзя: плагин, ушедший в `while True`, забирал бы поток
ядра и Рина замолкала бы целиком.

Что из этого следует для автора:

- **у вызова есть срок.** Не ответили за десять секунд — плагин считается
  сбойным и убивается. Долгую работу делайте в потоке и отвечайте сразу;
- **не печатайте в `stdout`.** Там наш провод. `print` испортит кадр
  посреди сообщения — пользуйтесь `self.ctx.log`;
- **состояние не переживает выключение.** Всё, что должно жить, кладите в
  свои настройки.

**И честно о границе.** Отдельный процесс — не песочница. Плагин идёт тем
же интерпретатором с теми же правами: разрешения честны в отношении
объявленных инструментов и ничего не обещают в отношении Python. Ставить
чужой плагин — решение того же уровня, что запустить скачанную программу.
Записано в [модели угроз](../security/THREAT-MODEL.md), угроза T-06.

## Совместимость

Манифест указывает `api_version`. Текущая — **4**; ядро загружает только
её.

Плагин версий 1–3 не загрузится, и человеку будет сказано, почему: причина,
нужная версия и что делать. Молчаливое «плагин просто не работает» выглядит
как поломка Рины, а не как устаревший плагин.

Что убрано в 4: `create_page()` и `open_window()`. Готовый виджет привязывал
ядро к конкретной оболочке — это был прямой блокер разделения процессов.

## Как проверить, что получилось

```bash
python tools/test_plugins.py
```

Проверка поднимает настоящий менеджер, ставит плагин, включает, спрашивает
страницу, жмёт кнопку и убеждается, что сосед цел, когда один плагин
завис.

Три примера в дереве, от меньшего к большему:
[`plugins/greeter/`](../../plugins/greeter/) — только `on_command`;
[`plugins/dice/`](../../plugins/dice/) — инструмент с аргументом;
[`plugins/notes/`](../../plugins/notes/) — страница, настройки, инструмент.
