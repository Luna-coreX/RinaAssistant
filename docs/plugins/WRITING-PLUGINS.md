# Как написать плагин

Задача плана `4.0-I05`. Решение об API — [ADR 0010](../adr/0010-plugin-api.md).
Полная справка — на сайте, [rina-assistant.com/dev/plugins](https://www.rina-assistant.com/dev/plugins/):
она собирается из кода, и её таблицы совпадают с этой версией API. Здесь —
короткий путь от пустой папки до работающего плагина.

Плагин — папка в `plugins/` с двумя файлами: `plugin.json` и `main.py`.

---

## Главное правило

**Плагин объявляет, что умеет, а когда и что выполнять, решает ядро.**

Объявляет он три вещи, и все три — данными:

- **инструменты** — что он умеет; уходят в реестр ядра и получают там
  разрешения, подтверждения и журнал наравне со встроенными;
- **вкладку** — как он выглядит; описанием, без виджетов;
- **разрешения** — что ему нужно от машины; списком в манифесте, до
  первого запуска.

Почему так. Ядро спрашивает у пользователя согласие на «запуск программ» и
без него отказывает. Плагин, который сам зовёт `subprocess`, обошёл бы этот
вопрос, и согласие пользователя ничего бы не значило.

## Самый маленький плагин

`plugins/greeter/plugin.json`:

```json
{
  "id": "greeter",
  "name": "Приветствие",
  "version": "1.0.0",
  "api_version": 4,
  "description": "Отвечает на «привет»",
  "permissions": []
}
```

`plugins/greeter/main.py`:

```python
from plugins.api import Plugin


class GreeterPlugin(Plugin):
    def on_command(self, text):
        if "привет" in text.lower():
            self.respond("Привет! Чем помочь?")
            return True
        return False
```

`on_command` возвращает `True`, если фраза его. Вернул `False` — фраза идёт
дальше.

**Фраза приходит к плагинам раньше встроенных команд**, по очереди в
алфавитном порядке id. Плагин, который откликается на любое «открой»,
перебьёт встроенный запуск программ, поэтому берите только своё: узкий набор
начальных слов надёжнее поиска слова внутри фразы. И отвечайте быстро —
каждая фраза идёт в ваш процесс, и пока плагин думает, Рина молчит.

`api_version` обязателен: без него считается 1, и плагин не загрузится.

## Инструмент

Инструмент — действие, которое ядро выполняет от имени плагина. Плагин
описывает его и ждёт вызова.

```python
import random

from core.tools import Param
from plugins.api import Plugin, PluginTool


class DicePlugin(Plugin):
    def tools(self):
        return [PluginTool(
            name="roll",
            summary="Бросить кубик.",
            params=(Param("sides", "integer", "Сколько граней.",
                          required=False, minimum=2, maximum=100, default=6),),
            run=self._roll,
        )]

    def _roll(self, args):
        return f"Выпало: {random.randint(1, args['sides'])}"
```

- Имя внутри плагина короткое: ядро само добавит префикс `plugin.dice.`,
  чтобы два плагина с инструментом `roll` не спорили за одно имя.
- Аргументы описываются тем же `Param`, что у встроенных инструментов:
  имя, тип и описание обязательны. Реестр проверяет их до вызова и
  подставляет умолчание, если аргумент не пришёл.
- `run` возвращает текст ответа; исключение становится неудачей инструмента,
  а трассировка уходит в журнал плагина.

**В 4.0 объявленные инструменты заводятся в реестр, но вызвать их пока
нечем** — ни фраза, ни своя команда, ни протокол к реестру по имени не
обращаются. Это задача `4.0-H10`. Голосом плагин сегодня работает через
`on_command`, как все примеры в `examples/plugins/`.

## Разрешения

Каталог разрешений **один** — тот же, что у ядра (`core/permissions.py`).

Плагину из него никогда не выдаются:

- `system.power` — выключение и перезагрузка;
- `files.write` — запись файлов;
- `screen.read`, `input.synthesize` — зарезервированы под 5.0.

Инструмент, которому нужно не выданное или не перечисленное в манифесте,
**не заводится вовсе**, а в журнале плагина остаётся строка, почему.

Подтверждение перед каждым вызовом просит `confirm_required=True`; для
опасного разрешения оно обязательно:

```python
PluginTool(name="clear", summary="Стереть заметки.",
           confirm_required=True, run=self._clear)
```

## Вкладка

Плагин описывает вкладку списком элементов, а рисует их оболочка. Поэтому
плагин не импортирует ни Qt, ни WPF.

```python
from plugins.api import Plugin
from plugins.page_spec import Button, Card, Items, Note, Row, Title


class NotesPlugin(Plugin):
    page_title = "Заметки"      # как назвать вкладку в колонке

    def page(self):
        notes = self.ctx.get_setting("items", []) or []
        return [
            Card([
                Title("Мои заметки"),
                Note(f"Всего: {len(notes)}"),
                Items(notes) if notes else Note("Пока пусто"),
            ], title="Заметки"),
            Row([
                Button("Очистить", action="clear", variant="danger"),
                Button("Обновить", action="refresh"),
            ]),
        ]

    def on_action(self, action, value=None):
        if action == "clear":
            self.ctx.set_setting("items", [])
```

После каждого действия вкладка собирается заново: плагин описывает своё
текущее состояние.

**Схема смысловая.** Полей о цвете, отступе и шрифте в ней нет: плагин
говорит «предупреждение» (`Badge(..., "warn")`), а как его показать, решает
оболочка. Все виды элементов — [PAGE-SCHEMA-v2](PAGE-SCHEMA-v2.md).

Плитка на главном экране описывается так же, методом `home()`. Главный экран
общий, поэтому пустой ответ правилен для большинства плагинов; на плитку
попадают первые четыре элемента, и рисуют её часто — собирайте её из того,
что уже знаете.

## Настройки плагина

Значения хранит **ядро**: плагину не нужно знать, где они лежат, и они
переживают его собственное падение.

- `self.ctx.get_setting(key, default)` и `self.ctx.set_setting(key, value)`
  читают и пишут одно значение; значение должно переживать JSON.
- `self.setting(key, default)` вернёт сохранённое, иначе умолчание из
  `settings_schema()`, иначе `default`.

```python
from plugins.settings_spec import Slider, Text, Toggle


def settings_schema(self):
    return [
        Text("prefix", "Приставка", default="•"),
        Toggle("timestamps", "Ставить время", default=True),
        Slider("limit", "Сколько хранить", min=10, max=500, default=100),
    ]
```

**Панель настроек по схеме оболочка в 4.0 ещё не строит** — это задача
`4.0-H08` на 4.0 Stable. Сейчас схема даёт умолчания для `self.setting()`;
если пользователю нужно что-то менять, дайте поле или кнопки на своей
вкладке.

## Что доступно через `self.ctx`

| Метод | Что делает |
|---|---|
| `respond(text)` | Рина скажет и покажет текст |
| `log(message)` | строка в журнал плагина |
| `get_setting(key, default)` | своя настройка |
| `set_setting(key, value)` | записать свою настройку |
| `notify(title, message)` | уведомление |

Всё. Ни запуска программ, ни доступа к соседям, ни файловой системы: то,
что плагин умеет делать с миром, объявлено инструментами и проходит через
реестр.

## Жизненный цикл

```
    обнаружен  →  включён  →  работает  →  выключен
    (манифест     (процесс    (фразы,       (on_disable,
     прочитан,     поднят,     вкладка,      процесс
     код НЕ        on_enable)  плитка)       завершён)
     запущен)
```

Код плагина запускается при **включении**: иначе сбойный плагин мешал бы
уже старту Рины. При выходе из Рины `on_disable` не зовётся — процесс
получает `plugin.shutdown` и завершается.

Хуки все необязательны: `on_enable`, `on_disable`, `on_command`, `tools`,
`page`, `home`, `on_action`, `settings_schema`. Есть и `on_event`, но в 4.0
ядро не рассылает плагинам событий (задача `4.0-H09`).

## Плагин живёт в своём процессе

С `4.0-H07` каждый плагин — отдельный процесс. Ошибку можно поймать,
бесконечный цикл — нельзя: плагин, ушедший в `while True`, забирал бы поток
ядра, и Рина замолкала бы целиком.

Что из этого следует для автора:

- **у вызова есть срок.** Не ответили за десять секунд — плагин
  останавливается, и в списке плагинов видна причина. Долгую работу делайте
  в своём потоке и отвечайте из памяти;
- **`print` не ломает провод:** хост отправляет его в поток ошибок, а тот
  попадает в журнал плагина. Для сообщений о работе всё же есть
  `self.ctx.log`;
- **состояние не переживает выключение.** Всё, что должно жить, кладите в
  свои настройки.

**И честно о границе.** Отдельный процесс — не песочница. Плагин идёт тем
же интерпретатором с теми же правами: разрешения честны в отношении
объявленных инструментов и ничего не обещают в отношении Python. Ставить
чужой плагин — решение того же уровня, что запустить скачанную программу.
Записано в [модели угроз](../security/THREAT-MODEL.md), угроза T-06.

## Совместимость

Манифест указывает `api_version`. Текущая — **4**; ядро загружает только
её. Плагин версий 1–3 не загрузится, и пользователь увидит в списке
плагинов причину, нужную версию и что делать.

Что убрано в 4: `create_page()` и `open_window()`. Готовый виджет привязывал
ядро к конкретной оболочке — это был прямой блокер разделения процессов.

## Как проверить, что получилось

```bash
python tools/test_plugins.py
```

Проверка собирает во временной папке плагины поставки и примеры, поднимает
настоящий менеджер, ставит плагин, включает, спрашивает вкладку, жмёт кнопку
и убеждается, что сосед цел, когда один плагин завис. В `plugins/`
репозитория она ничего не пишет.

Примеры лежат в [`examples/plugins/`](../../examples/plugins/) и в
установщик не входят: в `plugins/` — только то, что получает пользователь.
Чтобы попробовать пример, скопируйте его папку в `plugins/`. От меньшего к
большему:
[`greeter`](../../examples/plugins/greeter/) — только `on_command`;
[`dice`](../../examples/plugins/dice/) — инструмент с аргументом;
[`notes`](../../examples/plugins/notes/) — вкладка, настройки, инструмент;
[`convert`](../../examples/plugins/convert/) — плитка с полем ввода и свой модуль.
