# Инвентаризация поведения 3.1.0

- **Задача плана:** `4.0-A01`
- **Дата:** 1 сентября 2026
- **Источник:** код 3.1.0, а не память. Каждая ветка ниже прочитана в файле, ссылки на который указаны.

## Зачем это

Порт на C# проверяется сравнением с этим документом. Правило рубежа 4.0-port — «любое расхождение с 3.1 есть баг, а не замысел», и чтобы им пользоваться, надо иметь записанным, чем 3.1 является.

Отсюда же выводится `4.0-A02` (golden utterances): каждая строка раздела «Намерения» становится набором проверочных фраз. Поверхность интерфейса описывает отдельный документ `4.0-A06`; здесь только поведение.

Документ описывает, **что происходит**, а не что должно происходить. Все неочевидные ветки проверены запуском, а не только чтением: одно утверждение первой редакции оказалось неверным именно так. Замеченные странности помечены как **⚠ странность** и переносятся в порт как есть — решение менять их принимается отдельно, иначе порт превращается в переделку.

## 1. Как фраза становится действием

### Источники ввода

| Источник | `source` | Слово активации | Откуда |
|---|---|---|---|
| Строка ввода в окне | `typed` | не требуется | `main_window._on_typed_command` |
| Плавающая строка команд | `typed` | не требуется | та же |
| Разовое распознавание (хоткей, кнопка микрофона) | `voice` | **не требуется** — пользователь уже позвал явно | `engine._listen_worker` |
| Режим «всегда слушать» | `always` | **требуется** | `engine._always_worker` |

Все четыре пути кладут фразу в одну очередь (`engine.handle_command_async`), поэтому команды обрабатываются по одной и по порядку. Режим «всегда слушать» ждёт завершения предыдущей фразы, остальные — нет.

### Слово активации

Берётся из `wake_words` (список), при пустом списке — из `wake_word` (по умолчанию «Рина»). Сопоставление нечёткое: распознавание ошибается, и «Рита», «Ирина» тоже проходят (`voice/wake.py`, порог `wake_sensitivity`, по умолчанию 0.8).

- Слово активации найдено, после него есть текст → команда = текст после слова.
- Слово активации найдено, после него пусто → ответ «Да? Слушаю.» **кроме режима «всегда слушать»** — там молчание, иначе Рина услышит собственный ответ и зациклится.
- Слова активации нет → **полное молчание**, в историю ничего не пишется.

### Порядок конвейера

`core/engine.py`, `handle_command`. Первый сработавший обработчик завершает разбор.

| № | Стадия | Условие пропуска дальше |
|---|---|---|
| 0 | Ответ на незакрытый вопрос | нет вопроса, вопрос старше 60 с, или ответ не распознан как ответ |
| 1 | Плагины | ни один плагин не взял фразу |
| 2 | Пользовательские команды | ни одна не совпала |
| 3 | Таймеры, будильники, напоминания | фраза не про время |
| 4 | Управление системой и медиа | фраза не совпала с действием |
| 5 | Запуск программ по индексу | фраза не про запуск |
| 6 | Встроенные: счёт, поиск, простые ответы | ничего не подошло |
| 7 | Локальная модель | модель выключена |
| 8 | Запасной веб-поиск, иначе отказ | — |

Пустая строка не доходит даже до нулевой стадии: `handle_command` выходит сразу.

## 2. Намерения по стадиям

### Стадия 0 — ответ на незакрытый вопрос

Рина задаёт три вида вопросов. Все живут **60 секунд** (`PENDING_TTL`), после чего вопрос считается неактуальным и фраза разбирается как новая команда.

Новая команда, распознанная как команда, **снимает** незакрытый вопрос: иначе «второй» ответило бы на давно забытый выбор.

**Вид 1: выбор программы** (`choose_app`)

- Ответ порядковым: «второй», «два», «2» → берётся вариант по номеру.
- Ответ именем: «obs studio» → сопоставление по имени среди предложенных.
- Отказ: слова отмены → «Хорошо, отменяю.»
- Ответ не распознан → **вопрос снимается**, фраза разбирается как новая команда. Проверено: после этого вернуться к выбору нельзя.
- Побочный эффект успеха: выбор запоминается как алиас, в следующий раз запуск без вопроса.

**Вид 2: подтверждение системного действия** (`confirm_action`)

- Согласие: `да, давай, подтверждаю, точно, выключай, перезагружай, усыпляй, ага, yes, confirm` → действие выполняется.
- Отказ: `нет, отмена, отмени, не надо, стоп, no, cancel` → «Хорошо, отменяю.», запись в журнал безопасности.
- Невнятный ответ → **действие не выполняется, и вопрос снимается**. Проверено: сказать «выключи компьютер», затем что-то постороннее, затем «да» — ничего не произойдёт.

**Вид 3: подтверждение пользовательской команды** (`confirm_command`) — то же, но выполняется команда пользователя.

⚠ **Странность:** согласие и отказ проверяются по вхождению слова в список слов фразы. «Нет, давай» содержит и «нет», и «давай»; отказ проверяется первым и побеждает.

### Стадия 1 — плагины

Каждый включённый плагин получает фразу. Первый, вернувший истину, завершает разбор. Сбой плагина пишется в журнал и **не прерывает конвейер** — разбор продолжается со стадии 2.

Встроенные плагины: `clock`, `dice`, `greeter`, `notes`.

### Стадия 2 — пользовательские команды

Шесть типов: запуск программы, открытие папки, открытие сайта, произнесение текста, системное действие, последовательность шагов с паузами.

Сопоставление: точное (`exact`) или по вхождению (`contains`) — настройка команды.

Если команда содержит системное действие выключения или перезагрузки, сначала задаётся вопрос: «Команда «X» выключит или перезагрузит компьютер. Точно выполнить?»

Побочные эффекты: `os.startfile` для программ и папок, открытие браузера для сайтов, системные действия, счётчик запусков команды.

Цель, похожая на путь, проверяется на существование. Если пути нет — «Не нашла «X» — программу удалили или перенесли.» Короткое имя вроде `discord` путём не считается и отдаётся системе как есть.

### Стадия 3 — таймеры, будильники, напоминания

Срабатывает, только если во фразе есть слово-триггер: таймер (`таймер, засеки, засечь, timer`), напоминание (`напомни, напоминание, напомнить, remind`), будильник (`разбуди, будильник, подъём, alarm`), список (`какие таймеры, мои напоминания, что запланировано`, …), отмена (`отмени таймер, убери напоминания, отмени все таймеры`, …).

**Разбор срока.** Складываются все пары «число + единица»: «1 час 30 минут» → 5400 секунд. Отдельно распознаются «полчаса» и «полтора часа». Числительное может быть опущено: «через час» → 3600. Единицы: секунды, минуты, часы, в русских и английских формах. Верхняя граница — 10 лет, всё сверх обрезается.

**Разбор времени.** «в 15:00», «в 7 30», «в 9 утра». Отрицательный просмотр не даёт спутать «на 10 минут» (длительность) с «в 10:00» (время).

Ответы: «Засекла {срок}.» / «Напомню через {срок}: {текст}.» / «Разбужу в {время}.» / «Напомню в {время}: {текст}.» / «Запланировано: …» (до пяти) / «Ничего не запланировано.» / «Отменила: {N}.» / «Нечего отменять.»

Побочный эффект: запись в хранилище, переживает перезапуск.

### Стадия 4 — управление системой и медиа

Одиннадцать действий. Сопоставление в два прохода: сначала точное вхождение от длинных фраз к коротким (чтобы «выключи звук» не срабатывало как «выключи компьютер»), затем неточное — для оговорок и ошибок распознавания.

Порядок между проходами важнее длины. Пока проход был один, «убавь громкость» делала **громче**: неточное сравнение считает её похожей на «прибавь громкость» (0.875 при пороге 0.82), а та длиннее и проверялась первой. Найдено набором golden utterances, исправлено.

| Действие | Подтверждение |
|---|---|
| скриншот, громче, тише, выключи звук | нет |
| следующий трек, предыдущий трек, пауза | нет |
| заблокируй компьютер | нет |
| усыпи компьютер, перезагрузи, выключи компьютер | **да** |

Скриншот выполняется не здесь: ядро посылает оболочке событие, потому что захват экрана — операция Qt. Файл кладётся в «Изображения», имя `rina_ГГГГ-ММ-ДД_ЧЧ-ММ-СС.png`.

Ответы: «Прибавила громкость.», «Убавила громкость.», «Переключила звук.», «Следующий трек.», «Предыдущий трек.», «Готово.», «Блокирую компьютер.», «Отправляю компьютер в сон.», «Выключаю компьютер.», «Перезагружаю компьютер.», «Не получилось выполнить действие.»

### Стадия 5 — запуск программ

Фраза распознаётся как запуск по глаголу (`запусти`, `открой`, …); из остатка убираются служебные слова и получается цель.

Порядок разрешения:

1. **Выученный алиас** — то, что пользователь показал руками, важнее поиска.
2. **Поиск по индексу**, до 5 кандидатов. Учитывается транслитерация («телеграм» → Telegram) и нечёткое сопоставление.
3. **Запасной каталог** — если индекс пуст (не Windows).

Четыре исхода:

| Исход | Когда | Что происходит |
|---|---|---|
| `launched` | один кандидат, или явный лидер по отрыву, или запрос роли («браузер») | «Запускаю {имя}.» |
| `ambiguous` | несколько сопоставимых | «Нашла несколько: A, B, C. Какое запустить?» + вопрос вида 1 |
| `not_found` | кандидатов нет | «Не нашла программу «X».», звук ошибки, событие оболочке |
| `not_found` | кандидат есть, но запуск не удался | «Не получилось запустить {имя} — программу удалили или перенесли.» |

При `not_found` оболочка предлагает указать файл вручную — **но только если окно на экране**: выдёргивать диалог поверх чужой полноэкранной работы из-за неудачной голосовой команды нельзя.

Приложения Магазина запускаются по идентификатору, и он сверяется с индексом до запуска.

### Стадия 6 — встроенные

**Счёт.** Выражение вычисляется разбором дерева, не `eval`. Допускается либо явный триггер (`посчитай`, `сколько будет`, `вычисли`, …), либо «голое» выражение вида `2+2`. Проценты («20% от 3000») — по тому же правилу. Степень ограничена. Деление на ноль → «На ноль делить нельзя.» Ответ: «Получается {результат}.»

**Явный веб-поиск.** Триггеры: `найди, поищи, загугли, погугли, поиск, search, google, look up`. Открывает браузер выбранным поисковиком (Google, Яндекс, DuckDuckGo, Bing).

**Простые ответы.** «как тебя зовут» / «твоё имя» → «Меня зовут Рина, я твой голосовой ассистент.» «спасибо» → «Всегда пожалуйста!» «что ты умеешь» → перечисление возможностей.

### Стадия 7 — локальная модель

Только если включена в настройках (по умолчанию выключена). Вопрос уходит в фоновый поток; на время ожидания оболочке шлётся признак «думает».

Контекст — последние 6 реплик истории. Обращение идёт **только** на адрес из настроек.

Если модель не ответила или ответила ошибкой — поведение ровно такое же, как если бы её не было: переход к стадии 8.

### Стадия 8 — запасной поиск или отказ

Если включён запасной веб-поиск **и источник не «всегда слушать»** — фраза уходит в поисковик: «Поищу в интернете…». В режиме «всегда слушать» поиск не делается: туда попадают шум и случайная речь, открывать по ним браузер нельзя.

Иначе — «Извини, я не поняла команду.» со звуком ошибки.

## 4. Краевые случаи

| Ввод или состояние | Поведение |
|---|---|
| Пустая строка | Ничего. В историю не пишется. |
| Только слово активации | «Да? Слушаю.» В режиме «всегда слушать» — молчание. |
| Речь без слова активации в режиме «всегда слушать» | Полное молчание. |
| Очень длинный ввод (10 000 символов) | Проходит конвейер, доходит до отказа или поиска. Не падает. |
| Неоднозначное имя программы | Вопрос с тремя вариантами; ответ запоминается. |
| Отказ от подтверждения | «Хорошо, отменяю.», запись в журнал безопасности, действие не выполняется. |
| Невнятный ответ на подтверждение | Действие **не** выполняется, вопрос снимается; фраза идёт как новая команда. Позднее «да» уже ни к чему не относится. |
| Вопрос старше 60 секунд | Снимается; фраза разбирается заново. |
| Битый файл истории или напоминаний | Испорченные записи отбрасываются, вкладка работает. |
| Абсурдный срок напоминания | Обрезается до 10 лет. |
| Деление на ноль | «На ноль делить нельзя.» |
| Модель включена, но сервер недоступен | Ведёт себя как при выключенной модели. |
| Распознавание выключено | Микрофон недоступен, текстовый ввод работает. |
| Озвучка «silent» | Ответы только текстом. |
| Программа из индекса удалена | «Не получилось запустить X — программу удалили или перенесли.» |
| Сбой плагина | Пишется в журнал, конвейер продолжается. |
| Сбой в обработке команды | «Не получилось выполнить команду: …», очередь продолжает работать. |

## 5. Поверхности вне конвейера команд

**Глобальные хоткеи** (шесть действий): слушать, режим «всегда слушать», показать/скрыть окно, вкл/выкл озвучку, фокус на строку команд, плавающая строка. Повторные срабатывания при удержании подавляются окном 300 мс.

**Срабатывание напоминания.** Фоновый поток проверяет раз в секунду; сработавшее помечается выполненным и уходит событием в оболочку.

**Трей:** открыть, статус, выход. Пересобирается при смене темы и языка.

**Первый запуск:** мастер настройки.

**Проверка обновлений:** при старте, если включена; сверка с GitHub Releases.

**Действия над окном из ядра:** скриншот, свернуть, показать, выйти.

## 6. Проверяется автоматически

Поведение из этого документа закреплено набором [`golden/utterances.json`](golden/utterances.json) — 112 случаев, прогоняются командой:

```
python tools/golden_runner.py
```

Набор — исполняемая часть инвентаря: он ловит расхождения, которые чтением не видны, и это уже подтвердилось найденным дефектом громкости.

## 7. Что перенести в порт как есть

Помеченные выше **⚠ странности** — поведение 3.1.0, и порт обязан их воспроизвести, иначе golden-набор покажет расхождение там, где его не задумывали. Список для отдельного решения после порта:

1. «Нет, давай» трактуется как отказ (отказ проверяется раньше согласия).
2. Строка из одних пробелов отвечает «Да? Слушаю.», хотя пустая строка молчит: обрезка даёт пустую команду, а не пустой ввод, и это разные ветки.
3. Любая нераспознанная реплика молча снимает незакрытый вопрос. «Выключи компьютер» → «секунду» → «да» не выключит компьютер: подтверждение исчезло на второй фразе, и пользователю об этом не сказали. Для опасных действий это осторожная сторона ошибки, для выбора программы — потерянный вопрос.
