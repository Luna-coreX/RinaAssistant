# Голос Рины: свёрток для аренды

Всё, что нужно, чтобы за пару часов на арендованной карте получить голос Рины в Piper. Собрано после того, как то же самое делалось здесь неделю — записаны не только шаги, но и шесть мест, где они не работают.

## Что здесь

Свёрток самодостаточен: всё, что нужно, внутри, докачивать по месту — только VoxCPM2 и окружение Piper.

| | размер | |
|---|---|---|
| `rina-voice-v1.wav` | 300 КБ | **канонический голос Рины**, 3.2 с. Не пример — сам голос; всё остальное синтезируется с него |
| `resume-epoch4396.ckpt` | 807 МБ | чекпойнт на 257 эпохах дообучения, продолжать с него |
| `piper-data2/` | 21 МБ | нынешний набор, 181 запись. Новый материал **добавляется** к нему, а не заменяет |
| `texts.txt` | 74 КБ | 700 фраз, отобранных по покрытию звуковых переходов |
| `campplus.onnx` | 27 МБ | сеть верификации для проверки личности |
| `scripts/1_generate.py` | | VoxCPM2 озвучивает фразы голосом Рины |
| `scripts/2_prepare.py` | | приводит записи к виду, который берёт Piper |
| `scripts/3_fix_checkpoint.py` | | чинит **чужой** чекпойнт; нашему не нужен |
| `scripts/4_measure.py` | | проверяет, что получилась Рина и что она никому не принадлежит |

`resume-epoch4396.ckpt` сделан здесь и загружается как есть — проверено, `weights_only=True` его берёт, 46 гиперпараметров. Скрипт починки нужен только если начинать заново от `ru/ru_RU/irina/medium`.

## Подготовка машины

Образ — **Ubuntu 24.04 LTS с CUDA**. У 26.04 системный Python 3.14, под который колёс нет у половины стека, и выяснять это на оплаченном времени дорого. Пометка «BIOS» в названии образа означает режим загрузки виртуальной машины и к делу не относится.

Версия CUDA в образе почти не важна: `torch` привозит свой рантайм в колесе, от системы нужен только драйвер, а на CUDA-образе он свежий. RTX 6000 Ada — это `sm_89`, её держит любой `torch` начиная с cu121.

```bash
sudo apt-get update
sudo apt-get install -y build-essential python3-dev espeak-ng git
```

`espeak-ng` обязателен: Piper через него превращает текст в фонемы, без него обучение не стартует. `build-essential` нужен для компиляции выравнивания — см. ниже.

Если образ всё-таки 26.04, окружение ставится на свою версию Python, PPA для этого не нужен:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
uv python install 3.12
uv venv --python 3.12 && source .venv/bin/activate
```

Одной карты достаточно. Piper через Lightning на двух потребует `--trainer.devices 2` и другого эффективного размера пачки, а выигрыш на наборе такого размера — минуты, не часы.

## Порядок

```bash
python scripts/1_generate.py                    # ~30 мин на карте, ~сутки на процессоре
python scripts/2_prepare.py                     # минуты
# объединить dataset/ с принесённым piper-data2/ — и wav, и строки metadata.csv

python -m piper.train fit \
  --data.voice_name rina \
  --data.csv_path dataset/metadata.csv \
  --data.audio_dir dataset/wav \
  --data.espeak_voice ru \
  --data.cache_dir dataset/cache \
  --data.config_path dataset/config.json \
  --data.batch_size 32 \
  --data.trim_silence false \
  --model.sample_rate 22050 \
  --ckpt_path resume-epoch4396.ckpt \
  --trainer.accelerator gpu --trainer.devices 1 \
  --trainer.max_epochs 4696 \
  --trainer.default_root_dir train/

python scripts/4_measure.py <куда синтезировали>
```

## Шесть мест, где это не работает

Ни одно из них не описано в руководстве Piper: оно написано про Linux, свежие версии и `apt-get`.

На Ubuntu третье отпадает совсем: `PosixPath` там родной. Четвёртое отпадает, только если продолжать с нашего `resume-epoch4396.ckpt` — он чист, 46 гиперпараметров, все примитивные, ни одного объекта `pathlib`. От Irina оно никуда не денется.

**Обучающего кода нет в пакете.** `piper-tts` ставит `piper.train`, который импортирует `piper.train.vits`, а самого `vits` в колесе нет. Нужен исходник `OHF-Voice/piper1-gpl` той же версии, что и колесо.

**Выравнивание надо компилировать.** `piper/train/vits/monotonic_align/` приезжает без `core.pyx`. Файл берётся из исходника, собирается `python setup.py build_ext --inplace`, и результат кладётся в **вложенный** каталог `monotonic_align/` рядом с `__init__.py` — обёртка импортирует `.monotonic_align.core`.

**Чекпойнт не загружается.** Он записан на Linux и несёт `pathlib.PosixPath`: torch 2.6+ отвергает незнакомые классы, а Windows не умеет такой создать вовсе. Лечится `3_fix_checkpoint.py`.

**Командная строка отказывается стартовать.** В чекпойнте 98 гиперпараметров, из них 60 — настройки тренера прежних версий, которых модель не знает. Тот же скрипт их убирает.

**Обрезка тишины падает.** `pysilero_vad` сменил интерфейс; `--data.trim_silence false`, а обрезку делает `2_prepare.py`.

**Предел эпох должен быть больше, чем в чекпойнте.** Дообучение продолжает счёт, а не начинает заново: у `irina/medium` это 4139, и `--trainer.max_epochs 400` даёт отказ.

## Две ошибки, которые уже сделаны — не повторяйте

**Не нормируйте записи по пику поодиночке.** Первый набор так и готовился: каждая запись приводилась к 0.95, громкость выросла впятеро, разница между тихой и громкой фразой исчезла. Голос вышел прижатым к потолку — «плотнее и менее воздушно». Крест-фактор 5.3 против 7.9 у источника. `2_prepare.py` берёт **один множитель на весь набор**.

**Не режьте края впритык.** Пятидесяти миллисекунд мало: дыхание перед фразой и спад после неё — часть того, почему голос звучит неторопливым. В `2_prepare.py` запас 120 мс.

## Чего ждать по числам

Шкала не универсальна и читается по выборке: **разные люди — примерно до 0.54, тот же человек — около 0.86.**

| | |
|---|---|
| до канонического голоса | 0.79 на 96 эпохах, **0.82** при `length_scale` 1.25 |
| между репликами | 0.78–0.80 |
| до ближайшего живого диктора | 0.24–0.32 — то есть голос ничей |
| крест-фактор на выходе | 5.9–6.2 при 7.3 в материале; полторы единицы съедает вокодер `medium` |

Для сравнения: связка Edge + RVC давала 0.704 и стоила вдесятеро дороже в синтезе.

**`length_scale` 1.25 — не украшение.** Он не только попадает в темп канона (2.93 с против 2.94 на контрольной фразе), но и **улучшает сходство**: 0.791 на единице против 0.818 на 1.25. Темп входит в то, по чему узнают человека.

## Сколько эпох заказывать — меньше, чем кажется

Проверено на месте: личность выходит на полку примерно к 150 эпохам дообучения.

| эпох | до канона | между репликами | крест |
|---|---|---|---|
| 96 | 0.818 | 0.798 | 6.0 |
| **152** | **0.828** | 0.806 | 6.1 |
| 257 | 0.825 | 0.812 | 5.9 |

Почти втрое больший счёт сдвинул сходство с 0.818 до 0.825, а пик пришёлся на 152-ю — это шум. Устойчивость при этом ещё растёт, динамика стоит.

**Значит, тысяча эпох из руководства к нашему случаю не относится**, и оплаченное время лучше вкладывать в материал, а не в счёт. Триста с запасом, дальше смотреть на устойчивость, а не на сходство.

Отправная точка — чекпойнт `epoch=4396` (257 дообучения) с рабочей машины: продолжать с него, а не от Irina. Значит `--trainer.max_epochs 4696` — это 4396 плюс триста.

Подтверждено на слух: артефакты с эпохами стихают, поэтому триста осмысленны. Сходство при этом не вырастет — оно встало; растут устойчивость и чистота звучания.

## Что этим не чинится

**Дикция упирается в материал, а не в эпохи.** В первом наборе из 181 фразы все 53 звука русского присутствовали, но 173 перехода из 743 встречались **ровно раз**. Отсюда и претензии к дикции: звуки модель знает, переходы между ними учила с одного примера. Отобранные 700 фраз поднимают охват до 1148 переходов и снижают долю единичных с 23% до 9%.

**Потолок 22.05 кГц не двигается.** Это частота модели `medium`, и никакое обучение её не поднимет.

**Двуязычия Piper не даёт.** Он одноязычен по устройству. Английские названия программ либо сшиваются из кусков, либо требуют второй модели — английская Рина порождается тем же VoxCPM2 с того же образца.
