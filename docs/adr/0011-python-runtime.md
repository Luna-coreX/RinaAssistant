# ADR 0011. Какой Python уезжает к человеку

Дата: 2026-09-08 · Статус: принято · Задача: `4.0-I01`

## Вопрос

Рина 4.0 — две программы: оболочка на .NET и ядро на Python. Оболочка
собирается в файлы и вопросов не вызывает. Python — вызывает: его надо либо
взять с машины человека, либо привезти с собой, либо не привозить вовсе,
превратив ядро в исполняемый файл.

Три варианта, и выбор между ними определяет не только вес установщика.

## Решение

**Встроенный дистрибутив Python едет внутри установщика.**

Берётся `python-3.12-embed-amd64` с python.org, кладётся в
`<установка>/runtime/python/`, туда же ставятся зависимости ядра. Оболочка
запускает ядро **этим** интерпретатором и никаким другим.

Ни `PATH`, ни реестр не трогаются. Удаление — это удаление папки.

## Что решило выбор

Не размер. Размером три варианта отличаются терпимо: разница между лучшим
и худшим — десятки мегабайт при установщике под сотню.

Решило то, **что человек делает после установки**.

Продукт устроен так, что движки речи и плагины ставятся **потом**: движков
пять на синтез и пять на распознавание, и ни один не нужен всем.
Whisper тянет torch на пару гигабайт, Vosk требует скачанной модели,
Piper — файла голоса. Везти это в установщике нельзя, а значит после
установки должен остаться Python, **в который можно доставить пакет**.

Это отсекает замороженное ядро и делает системный Python опасным.

## Отвергнутые варианты

### Замороженное ядро (PyInstaller)

Один файл, Python не нужен вовсе. Отвергнуто.

Плагин — это Python, и его зависимости ставятся после установки Рины. В
замороженное ядро доставить пакет нельзя: у него нет ни `pip`, ни
`site-packages`, куда что-то положить. Пришлось бы либо запретить плагинам
зависимости, либо пересобирать ядро под каждый набор движков — то есть
собирать не программу, а её варианты.

Отдельно: `4.0-H07` даёт каждому плагину свой процесс, и этот процесс —
`python -m plugins.host`. Замороженное ядро умеет запускать себя, но не
умеет запускать *чужой* Python-модуль тем же интерпретатором.

### venv из Python, установленного на машине

Установщик маленький, обновления безопасности приходят от системы.
Отвергнуто, и это отказ с уже оплаченным опытом.

**Мы не контролируем версию.** В `core/speech.py` громкость считается
вручную, а не через `audioop`, потому что `audioop` **удалён в Python
3.13**. Мы знали об этом заранее и обошли. Но это один случай, который мы
поймали; на чужой машине версия меняется без нашего ведома, и следующий
такой случай станет письмом «Рина перестала слышать после обновления
системы» — с непонятно чего начинающимся разбором.

**Python может отсутствовать.** Тогда установщик обязан его поставить, то
есть привезти с собой, — и мы возвращаемся к встроенному дистрибутиву,
только через окно чужого установщика и с влиянием на всю машину.

**Отладка перестаёт быть воспроизводимой.** Диагностический пакет
(`4.0-I03`) называет версии четырёх частей; версия интерпретатора не
названа, потому что при своём Python она известна. С системным — не
известна, и её пришлось бы добавить пятой.

### Встроенный дистрибутив — принят

Ровно тот интерпретатор, на котором мы проверяли. Не зависит от того, что
стоит на машине. Не трогает `PATH` и не мешает другому Python. Убирается
удалением папки.

## Цена, которую платим

**Обновления безопасности Python — наша забота.** Системный Python
обновляет система; встроенный обновляем мы, выпуском. Это записано здесь
как обязательство, а не как забытая мелочь: рантайм — четвёртая вещь,
которую надо помнить при выпуске, наравне с оболочкой, ядром и схемой
данных.

**`embed` — не полный дистрибутив.** В нём нет `pip`, нет `tkinter`, нет
`ensurepip`, а `site-packages` включается правкой файла `._pth`. Всё это
делает сборка, и делает один раз; но человек, распаковавший `embed` руками,
получит не то же самое, и об этом сказано в `tools/build_release.py`.

**Вес.** Распакованный рантайм — около 25 МБ, плюс зависимости ядра.

## Что могло бы изменить решение

Если движки речи однажды перестанут быть внешними пакетами — например,
синтез уедет в оболочку целиком, — исчезнет главный довод, и замороженное
ядро станет разумным.

Если Python начнёт давать гарантию совместимости между младшими версиями,
довод против системного интерпретатора ослабнет, но не исчезнет: остаётся
«его может не быть».

## Следствия

- Оболочка ищет интерпретатор по порядку: рантайм рядом с собой → окружение
  проекта → `PATH`. Последнее — для разработки; у человека сработает
  первое.
- Установщик кладёт два рантайма и ничего не регистрирует в системе, кроме
  ярлыка и записи об удалении.
- Собранный выпуск проверяется запуском: `tools/check_release.py` поднимает
  ядро **привезённым** интерпретатором и доводит до рукопожатия. Установщик,
  который ставит нерабочее, — худший из возможных: он выглядит успешным.
