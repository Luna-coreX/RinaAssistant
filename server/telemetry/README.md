# Сборщик телеметрии беты

- **Задача плана:** `4.0b-D05`; уход в Stable — `4.0-S04`
- **Где работает:** Cloudflare Workers, хранилище — D1
- **Клиент:** [`core/telemetry.py`](../../core/telemetry.py)

## Что принимает и что хранит

Принимается один запрос: `POST /v1/report` с отчётом той формы, которую строит ядро. Проверка в `worker.js` так же строга, как сборка в ядре: ровно оговорённые поля, слова только из словаря программы (латиница в нижнем регистре, цифры, `_`, `.`, `:`), числа в пределах. Отчёт с лишним полем, с кириллицей или со строкой вне словаря отклоняется целиком.

Хранится только день получения и сам отчёт. Адрес, с которого он пришёл, и время суток не записываются; журнал наблюдений Cloudflare, где адреса были бы, выключен в `wrangler.toml`. От одной установки — не больше одного отчёта в день. Каждую ночь удаляется всё старше 180 дней.

## Развёртывание

Нужны учётная запись Cloudflare и `wrangler` (`npm install -g wrangler`).

```bash
cd server/telemetry
wrangler login
wrangler d1 create rina_telemetry
```

Идентификатор базы из вывода последней команды вписывается в `database_id` в `wrangler.toml`. Затем:

```bash
wrangler d1 execute rina_telemetry --remote --file schema.sql
wrangler deploy
```

`wrangler deploy` печатает адрес сборщика вида `https://rina-telemetry.<поддомен>.workers.dev`. Этот адрес с путём `/v1/report` вписывается в `ENDPOINT` в `core/telemetry.py`. Пока `ENDPOINT` пуст, программа ничего не отправляет, а страница «Что Рина знает обо мне» показывает накопленное как неотправленное.

## Проверка

Функцию `validate` из `worker.js` проверяет `tools/test_telemetry.py` через Node: отчёты, которые на самом деле строит ядро, должны приниматься, а испорченные — отклоняться. Без Node эта часть проверки пропускается и говорит об этом вслух.

## Уход в Stable

`4.0-S04`: в 4.0.0 Stable удаляются клиент в ядре, настройка, шаг мастера и группа на странице приватности, а сборщик выключается командой `wrangler delete` вместе с базой.
