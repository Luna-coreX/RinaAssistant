# Сборщик телеметрии беты

- **Задача плана:** `4.0b-D05`; уход в Stable — `4.0-S04`
- **Где работает:** Vercel Functions (регион `fra1`), хранилище — Postgres в Neon
- **Клиент:** [`core/telemetry.py`](../../core/telemetry.py)

## Что принимает и что хранит

Принимается один запрос: `POST /api/v1/report` с отчётом той формы, которую строит ядро. Проверка в [`validate.js`](validate.js) так же строга, как сборка в ядре: ровно оговорённые поля, слова только из словаря программы (латиница в нижнем регистре, цифры, `_`, `.`, `:`), числа в пределах. Отчёт с лишним полем, с кириллицей или со строкой вне словаря отклоняется целиком.

Хранится только день получения и сам отчёт. Адрес, с которого он пришёл, и время суток сборщик не записывает и в журнал ничего не пишет. От одной установки — не больше одного отчёта в день. Каждую ночь удаляется всё старше 180 дней.

**Журнал платформы.** Vercel сам ведёт журнал вызовов функций, и выключить его нельзя. На тарифе Hobby он хранится час, на Pro — сутки. Адрес запроса у платформы в этот срок есть: по нему работает её фильтр «запросы из моего браузера». Log Drains, которые выгружали бы журнал наружу и дольше, не подключаются.

**Тариф.** Hobby разрешён только для некоммерческого использования. Бета бесплатна и кода оплаты в программе нет, так что это в правилах. Если платное появится раньше, чем сборщик уйдёт со Stable, проект переезжает на Pro.

## Как устроен

| Файл | Что это |
|---|---|
| `validate.js` | форма отчёта; без зависимостей |
| `collector.js` | приём отчёта и ночная чистка, с хранилищем, переданным снаружи |
| `store.js` | хранилище: Neon по HTTP, `DATABASE_URL` |
| `api/v1/report.js`, `api/clean.js` | функции Vercel — тонкая обвязка над `collector.js` |
| `vercel.json` | регион и расписание чистки (`17 3 * * *`, раз в сутки) |
| `schema.sql` | таблица `reports` |

## Развёртывание

Нужны учётная запись Vercel и его CLI (`npm install -g vercel`).

1. Создать проект из этой папки:

   ```bash
   cd server/telemetry
   vercel link
   ```

   Если проект подключается из GitHub через панель, в его настройках **Root Directory** — `server/telemetry`.

2. В панели проекта: **Storage → Create Database → Neon**, регион — Frankfurt (`eu-central-1`), рядом с функцией. Интеграция добавит проекту строку подключения; код читает `DATABASE_URL` — проверьте в **Settings → Environment Variables**, что переменная называется так.

3. Создать таблицу: выполнить `schema.sql` в SQL Editor у Neon или

   ```bash
   psql "<строка подключения>" -f schema.sql
   ```

4. Секрет для ночной чистки — случайная строка не короче 16 символов:

   ```bash
   vercel env add CRON_SECRET production
   ```

   Без него чистка отвечает 401 любому, в том числе самому Vercel.

5. Выложить:

   ```bash
   vercel deploy --prod
   ```

Адрес сборщика — `https://<проект>.vercel.app/api/v1/report` (или свой домен, если подключить его к проекту). Он вписывается в `ENDPOINT` в `core/telemetry.py`; сейчас это `https://rina-telemetry.vercel.app/api/v1/report`.

**Проект — отдельный.** Сайт тоже живёт на Vercel, и если выложить сборщик в его проект, он заменит сайт на домене: так и случилось 2026-10-01. Папка `server/telemetry` привязывается к своему проекту (`rina-telemetry`). Пока `ENDPOINT` пуст, программа ничего не отправляет, а страница «Что Рина знает обо мне» показывает накопленное как неотправленное.

## Проверка

`tools/test_telemetry.py` запускает `validate.js` и `collector.js` через Node: отчёты, которые на самом деле строит ядро, должны приниматься, испорченные — отклоняться, а чистка — отвечать только на свой секрет. Хранилище в проверке подставное: база и развёртывание для неё не нужны. Без Node эта часть пропускается и говорит об этом вслух.

## Уход в Stable

`4.0-S04`: в 4.0.0 Stable удаляются клиент в ядре, настройка, шаг мастера и группа на странице приватности, а сборщик выключается: проект удаляется (`vercel project rm`), база в Neon — вместе с ним.
